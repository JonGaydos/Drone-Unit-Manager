# Alembic Adoption (main DB) — Design

Date: 2026-06-07
Project: Drone Unit Manager
Status: approved (build it)

## Context

The main database schema is currently built/updated by hand-rolled startup code:
`Base.metadata.create_all(bind=engine)` plus `run_migrations()` (a maintained
list of `ALTER TABLE ... ADD COLUMN` + index-creation + a one-time
has_telemetry backfill). This is fragile and manual; a column-default mismatch
in this scheme caused the 2026-06-06 login-500. Adopt **Alembic** (already in
`requirements.txt`, unused) so schema changes are explicit, ordered,
reviewable, and reversible.

The app is **not yet in production use by any org**; the Unraid test data is
disposable (CSV + Skydio API re-import available). So we adopt with the simplest,
lowest-risk path — a **fresh Alembic-built schema**, no `stamp`/adoption logic —
and reset + re-import on rollout.

## Scope

- **Main DB only** (`Base` / `engine`, `settings.DATABASE_URL`). Future schema
  changes go through Alembic.
- **Telemetry DB unchanged** — keeps its `create_all` + its small telemetry
  migration. Not brought under Alembic (one table, separate metadata).

## Components

- `backend/alembic.ini` — minimal config; `script_location = migrations`. The
  DB URL is supplied at runtime from `settings.DATABASE_URL` (not hard-coded in
  the ini).
- `backend/migrations/env.py` — wires Alembic to the app: imports `app.models`
  (so `Base.metadata` is complete), sets `target_metadata = Base.metadata`,
  reads the URL from `app.config.settings.DATABASE_URL`, runs offline+online,
  with `render_as_batch=True` (SQLite needs batch mode for ALTERs).
- `backend/migrations/versions/0001_baseline.py` — the initial migration,
  autogenerated from the current models; creates **every main-DB table + index**
  exactly as they exist today.
- `backend/migrations/script.py.mako` — standard template.

## Startup change (lifespan, the only runtime change)

In `main.py` lifespan, replace the **main-DB** `create_all` + the **main-DB**
portion of `run_migrations()` with a programmatic Alembic upgrade:
```python
from alembic.config import Config
from alembic import command
cfg = Config(<path to alembic.ini>)
command.upgrade(cfg, "head")
```
Keep, in order: telemetry `create_all` (+ the telemetry-DB migration if the
`TelemetryPoint` model does not already declare the `extra_data`/`source`
columns — verify; if the model declares them, telemetry `create_all` suffices
and the whole `run_migrations` can be dropped), then `seed_defaults()`, install
token, scheduler. Order matters: migrate -> seed.

The one-time **has_telemetry backfill is dropped** (it operated on existing
flight rows; on a fresh DB it is moot, and the refresh-path code fix that sets
the flag going forward remains).

## Schema parity (the must-verify invariant)

A fresh Alembic-built schema MUST equal what `create_all` builds today, or a
query could hit a missing column/index. Verification (automated, pre-merge):
build one SQLite DB via `Base.metadata.create_all`, build another via
`alembic upgrade head`, and diff `sqlite_master` (tables + indexes) and each
table's `PRAGMA table_info` (columns/types/nullability). They must match (modulo
the `alembic_version` table, which only the Alembic DB has). Any diff is fixed
by editing the baseline migration before shipping.

## Rollout (fresh build + re-import; no stamp)

1. Merge + CI builds the image.
2. On Unraid: stop the container, **reset `/app/data`** (or just delete the main
   `drone_unit_manager.db`), `docker compose pull && up -d`.
3. First boot: Alembic builds the schema from the baseline; seed runs; install
   token printed.
4. Re-import data: Skydio sync + the CSV/Excel importers + re-enter API keys.

## Non-goals
- No telemetry DB under Alembic.
- No `stamp`/auto-adopt logic (unnecessary — data is disposable pre-go-live).
- No data migration of the existing DB (it's reset).

## Verification
- Backend: `py_compile` + `import app.main`; the schema-parity diff test
  (create_all vs alembic upgrade) prints a PASS; `alembic upgrade head` then
  `alembic upgrade head` again is a clean no-op; a fresh empty DB upgrades to a
  working schema and `import app.main` + a trivial query works.
- CI build succeeds (alembic already installed; no Dockerfile change needed
  unless the migrations/ dir must be COPYed — verify the Dockerfile copies
  `backend/app` only and ADD `migrations` + `alembic.ini` to the image).

## Files
New: `backend/alembic.ini`, `backend/migrations/env.py`,
`backend/migrations/script.py.mako`, `backend/migrations/versions/0001_baseline.py`.
Modify: `backend/app/main.py` (lifespan), `backend/app/services/migrations.py`
(slim to telemetry-only or remove), `Dockerfile` (COPY migrations + alembic.ini
into the image so `alembic upgrade` can find them at runtime).
